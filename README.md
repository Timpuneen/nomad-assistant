# Insurance Assistant — ИИ-ассистент по страховому законодательству РК

Интеллектуальный ассистент для консультаций сотрудников страховой компании по законодательству Республики Казахстан. Построен на архитектуре RAG (Retrieval-Augmented Generation): загружаете Word-файлы с законами — система индексирует их в векторную базу данных — при вопросе находит релевантные нормы и генерирует точный ответ с указанием источника.

## Архитектура

```
Пользователь
    │
    ▼
React (Vite)          ← фронтенд
    │  HTTP/REST
    ▼
FastAPI               ← бэкенд
    │
    ├── RAG Engine
    │     ├── python-docx   (парсинг Word)
    │     ├── ChromaDB      (векторная БД, хранится локально)
    │     └── OpenAI API    (эмбеддинги + GPT-4o-mini)
    │
    └── /chroma_db/         (персистентное хранилище)
```

**Как работает RAG:**
1. При загрузке `.docx` — текст парсится, разбивается по статьям, каждый фрагмент превращается в вектор (embedding) через OpenAI и сохраняется в ChromaDB
2. При вопросе — вопрос тоже превращается в вектор, система находит 5 ближайших фрагментов из базы
3. Найденные фрагменты подаются в GPT-4o-mini как контекст → генерируется ответ со ссылками на статьи

## Запуск через Docker (рекомендуется)

Самый простой способ — одна команда поднимает всё. Docker образ устанавливает зависимости автоматически.

### 1. Создать .env файл

```bash
cd backend
cp .env.example .env
# Открыть .env и вставить OpenAI API ключ:
# OPENAI_API_KEY=sk-...
```

### 2. Положить законы в папку (опционально)

В корне проекта есть папка `laws/` — положите туда `.docx` файлы с законами до запуска:

```
laws/
  ГК_РК_страхование.docx
  ОСАГО.docx
  Закон_о_нотариусах.docx
```

При старте бэкенд автоматически проиндексирует все новые или изменённые файлы (проверка по MD5). Повторный `docker compose up` не переиндексирует то, что уже было загружено без изменений.

Чтобы подхватить новые файлы без пересборки:
```bash
docker compose restart backend
```

### 3. Собрать и запустить

```bash
# Из корня проекта (там где docker-compose.yml)
docker compose up --build
```

Первый запуск занимает 2–3 минуты (сборка образов).

После запуска:
- **Приложение:** http://localhost
- **API (для отладки):** http://localhost:8000/docs

### Полезные команды

```bash
# Запустить в фоне
docker compose up --build -d

# Посмотреть логи
docker compose logs -f

# Остановить
docker compose down

# Остановить и удалить данные ChromaDB
docker compose down -v
```

> **Данные ChromaDB** сохраняются в Docker volume `chroma_data` и переживают перезапуск контейнеров. При `down -v` данные удаляются — загруженные законы придётся переиндексировать.

## Установка и запуск (без Docker)

### 1. Клонировать репозиторий

```bash
git clone <repo-url>
cd insurance-assistant
```

### 2. Бэкенд

```bash
cd backend

# Создать виртуальное окружение
python -m venv venv

# Активировать
# Windows:
venv\Scripts\activate
# macOS/Linux:
source venv/bin/activate

# Установить зависимости
pip install -r requirements.txt

# Создать файл с переменными окружения
cp .env.example .env
# Открыть .env и вставить ваш OpenAI API ключ:
# OPENAI_API_KEY=sk-...

# Запустить сервер
uvicorn main:app --reload --port 8000
```

Бэкенд будет доступен на http://localhost:8000  
Swagger документация: http://localhost:8000/docs

### 3. Фронтенд

```bash
cd frontend

# Установить зависимости
npm install

# Запустить dev-сервер
npm run dev
```

Фронтенд будет доступен на http://localhost:5173

### Быстрый старт (краткая версия)

**С Docker:**
```bash
# 1. Настроить .env
cd backend && cp .env.example .env
# Добавить OPENAI_API_KEY в .env

# 2. Запустить
cd .. && docker compose up --build
# Открыть http://localhost
```

**Без Docker:**
```bash
# 1. Бэкенд
cd backend
python -m venv venv
source venv/bin/activate  # или venv\Scripts\activate на Windows
pip install -r requirements.txt
cp .env.example .env      # добавить OPENAI_API_KEY
uvicorn main:app --reload --port 8000

# 2. Фронтенд (в новом терминале)
cd frontend
npm install
npm run dev
# Открыть http://localhost:5173
```

## Использование

1. Откройте http://localhost:5173
2. В левой панели нажмите **«Загрузить закон (.docx)»** и выберите Word-файл с законом
3. Дождитесь индексации (система покажет количество проиндексированных фрагментов)
4. Задайте вопрос в поле ввода на русском или казахском языке
5. Ассистент ответит с указанием источника (название файла и номер статьи)

## API эндпоинты

| Метод | URL | Описание |
|-------|-----|----------|
| GET | `/api/stats` | Статистика базы знаний |
| GET | `/api/documents` | Список загруженных документов |
| POST | `/api/upload` | Загрузить и индексировать `.docx` |
| POST | `/api/chat` | Задать вопрос |
| DELETE | `/api/documents/{name}` | Удалить документ из базы |

Пример запроса к `/api/chat`:
```json
{
  "question": "Что такое страховая сумма?",
  "session_id": "user-123"
}
```

Пример ответа:
```json
{
  "answer": "Страховая сумма — это сумма денег, на которую застрахован объект страхования...",
  "sources": [
    { "source": "ГК_РК_страхование.docx", "article": "812" }
  ],
  "session_id": "user-123"
}
```

## Поддерживаемые форматы

- `.docx` — Word-документы (основной формат)
- Текст на русском и казахском языках

Для добавления законов с портала [adilet.zan.kz](https://adilet.zan.kz):
1. Откройте нужный закон на сайте
2. Сохраните/скопируйте текст в Word-документ
3. Загрузите через интерфейс

## Параметры системы (backend/rag.py)

| Параметр | Значение | Описание |
|----------|----------|----------|
| `EMBED_MODEL` | `text-embedding-3-small` | Модель для эмбеддингов |
| `CHAT_MODEL` | `gpt-4o-mini` | Модель для генерации ответов |
| `CHUNK_SIZE` | 800 символов | Размер одного фрагмента текста |
| `CHUNK_OVERLAP` | 150 символов | Перекрытие между фрагментами |
| `TOP_K` | 5 | Кол-во фрагментов для контекста |

Для повышения качества ответов можно увеличить `TOP_K` до 8 или сменить модель на `gpt-4o`.
